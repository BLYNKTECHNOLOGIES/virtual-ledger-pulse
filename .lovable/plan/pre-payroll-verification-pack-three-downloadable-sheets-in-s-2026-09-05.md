# Pre-payroll verification pack — three downloadable sheets in Step 7

Step 7 ("Run payroll on RazorpayX dashboard") is the last moment before money moves. Today it only links out to the RazorpayX dashboard. It will gain a **Download verification pack** action that produces three clearly formatted sheets covering everything this month's payroll is built on, so the whole month can be checked on one screen before the run.

Each sheet is one CSV. One click downloads all three; a second option downloads them as a single Excel file with three tabs (the project already has the Excel library, so no new dependency). Every sheet starts with a small header block: cycle month, generated on (IST), generated by, employee count, and a one-line status of the cockpit steps the data came from — so a saved copy is always self-explanatory.

## Sheet 1 — Leave and comp-off ledger

One row per employee, one clear block per leave type, so opening, movement and closing always add up.

- Identity: badge ID, name, department, date of joining, exit date (if leaving this month)
- For each leave type (Casual, Sick, and any other active type): opening balance, credited this month, taken (paid), taken (unpaid / beyond balance), used to absorb loss of pay, closing balance
- Comp-off block: opening, earned this month (with the worked dates count), taken as leave, used against loss of pay, encashed days, encashment amount, closing (0 — comp-off does not carry forward)
- A "balance check" column that flags any row where opening + credited − used does not equal closing

Sources: leave allocations, approved leave requests and their consumption records, the comp-off credit ledger and this month's comp-off settlement rows, plus the same ledger the Step 5 loss-of-pay calculation and Step 6 comp-off encashment produce.

## Sheet 2 — Additions and deductions (line level)

One row per money line, grouped and sorted so the same employee's lines sit together.

- Employee (badge, name), category, description, direction (addition / deduction), amount
- Category covers: loss of pay, comp-off encashment, recovery instalments (with instalment number and remaining balance), deposits, training / part-month CTC adjustments, one-time payments, F&F settlement lines, and manual staged rows
- Origin: automatic or manual, provisional or final, whether it was pushed to RazorpayX (date/time in IST), and whether the pushed value was read back and verified
- Rows already paid outside payroll are marked and excluded from the payable totals
- Closing totals block: total additions, total deductions, net effect, and counts of pushed / not pushed / unverified

Sources: staged additions and deductions, automatic recoveries, F&F settlements, deposit transactions.

## Sheet 3 — Payroll summary per employee (the holistic view)

One row per employee — the sheet to scan for anything that looks wrong.

- Identity and RazorpayX mapping status
- Attendance: calendar days, working days, present, half days, absent, paid leave, unpaid leave, holidays/weekly-offs worked, days still unverified, employment window if they joined or left mid-month
- Loss of pay: raw loss-of-pay days, days absorbed by comp-off, days absorbed by casual leave, final chargeable days, per-day rate with the divisor used (calendar days), loss-of-pay amount
- Money: monthly gross base and where that base came from, total additions, total deductions, expected net effect versus the base
- Flags column: no RazorpayX mapping, no salary base, unverified attendance days, negative net, balance mismatch from Sheet 1, staged but unpushed lines — anything worth a second look before running payroll

Sources: the attendance/loss-of-pay calculation used by Step 5, the comp-off calculation used by Step 6, the staged input tables, and the salary base resolver already used across the cockpit.

## Behaviour and safeguards

- The pack is generated read-only: the loss-of-pay and comp-off engines are called in preview mode, nothing is staged, pushed or settled by downloading.
- If a mandatory recalculation is stale (the existing Step 5/6 gates), the pack still downloads but says so in the header block and in the flags column, so no one verifies against outdated numbers.
- Amounts formatted plain (no currency symbol) so the sheets open cleanly in Excel; dates as DD-MM-YYYY, timestamps in IST.
- Presentation and export only — no change to any payroll calculation, staging, push or step gating.
