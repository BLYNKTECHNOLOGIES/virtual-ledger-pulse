# Workforce planning decisions

- Workforce staffing is computed only in the DB (hr_workforce_staffing_matrix: one line per role per planning shift, explicit seat_capacity_id, ATS progress); screens sum src/lib/hrms/workforce.ts per-line formulas and change requirement status only via hr_requirement_transition, because guessed scopes and netted totals miscounted.
- Workforce staffing reconciliation runs once per transaction at commit (row triggers mark hr_wf_reconcile_queue; a deferred constraint trigger runs hr_reconcile_capacity_hiring), because column-list and trigger-depth guards missed changes made by other triggers.
- The forecast projects per staffing line from matrix on-roll plus hr_workforce_forecast_events (src/lib/hrms/workforceForecast.ts); events off any line are listed but excluded from figures, because every forecast number must use the matrix's people and per-line gaps.
- The commit-time and nightly (cron, 01:15 IST) reconcile never waits on row locks (SKIP LOCKED; skipped lines are picked up next run) and refreshes requirements in one set-based pass, because waiting on another user's row while holding the reconcile lock deadlocks.
- People count on the shift whose schedule row covers today by its dates (work info only when none does), and in-progress onboarding on a training shift is allocated to one line by remaining need after on-roll trainees, because future shift changes and new trainees otherwise count on the wrong line or nowhere.
- Salary-budget per-person figures come only from a salary range or an average of at least 2 people (role, else department, else all planned staff), and departments under 2 people are grouped, because no figure may reveal one person's salary.
- A department head's "adds headcount" request carries adds_headcount; approving it raises the line's required number in the same transaction (refused on desk-following lines), because an approved addition that never changes the line just shows as over-requested.
- Overview figures follow the filters through each requirement's or person's line (date filters use open requirements' target joining dates); blocks that sit on no line say "all shifts", because lines carry no target date and unfiltered blocks contradicted the page.

- Workforce RLS policies call private.hr_wf_is_current_manager() (signed-in user only); hr_wf_is_manager(uuid) stays internal (no authenticated grant), because a uuid-taking check lets any user ask about anyone.
- Advisory-lock order is numbering (hr_next_hiring_requirement_no) then reconcile, and the line-overlap check runs only when department/roles/shifts change or a line becomes active, because the reconcile's own line updates taking the overlap lock in the other order deadlocked saves.
- A pending department "adds headcount" request covers nothing on its line; approval raises the line by N (pause re-signed) and cancelling an approved one lowers it by the unfilled part, because otherwise the reconcile cancels and re-raises the line's automatic request.
- Line priority is computed, never stored: hr_wf_priority_rule (mirrored by autoPriority in workforce.ts) inside the staffing matrix; hr_headcount_plans.priority is only HR's pin (NULL = automatic), and line-linked requests copy the line's priority (insert trigger + reconcile), because a stored priority went stale and screens disagreed.
- A role in planning must be on an active line before hiring: hr_wf_assert_role_planned guards every requirement insert and every non-closed job create/reopen; the screens read hr_wf_position_planning_status to show "Plan first", because a role with no line produced hiring nobody planned for.
- A position's department move carries its single-role lines, desk groups, open requests, live jobs, people, draft onboarding and users in one trigger (hr_wf_position_move_apply) under the hr.wf_position_moving flag that WF6's job/requirement checks honour, then validates the end state, because a half-moved position left lines empty and raised wrong requests.
